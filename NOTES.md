# NOTES.md — design decisions (v2, current design only)

- Data-driven content (classes/skills/monsters/rooms/vocab/prompts) in /content JSON; engine in /src; content validated on load with friendly errors naming file+problem (keeps teachers able to edit content safely).
- GM console is authoritative; it broadcasts the full state after every mutation; Stage requests state on load and retries until received (simplest correct two-window sync, BroadcastChannel).
- Single-window index.html = stage fullscreen + GM drawer toggled by hotkey G (teachers without a second screen).
- Engine is UI-agnostic: actions mutate state, UIs render from state (lets the same engine drive gm/stage/single-window and be tested headless).
- Stats = Might/Agility/Mind/Heart, modifier = stat - 3, all classes sum to 12 (balanced identity with a small spread).
- Action resolution = d20 + statMod + LanguageBonus + AssistBonus vs difficulty; nat 20 crit (auto-success, double damage dice), nat 1 fumble (auto-fail, fun narration) (classic, readable on a projector).
- Language Check Off/Light/Full adds a pre-roll "Say it" prompt; teacher grades Weak/Good/Great = +0/+2/+4; target/example hints are teacher-only (English supports, never gates, the game).
- Skills cost 1 Focus; Focus regens +1/round; basic attacks are free (a 0-Focus player can still fight).
- Exactly 3 skills per class, complementary roles (party without a healer/buffer should feel it).
- Spotlight rounds: only N characters act per round (default 4), fair rotating start; non-acting players may Assist (+1, max +2); dazed players may still Assist but not act (keeps 12-player combat short and inclusive).
- Monster HP scales with ACTING characters = min(party, spotlight): maxHp = base + (acting-1)*5; base HP tuned to 10/15/20 for lv1/2/3 by a competent-play simulation so median fight is 3-6 rounds for 1/4/8/12 players (worst median 5, cap triggers ~0 for 4+ players); 12-round monster-retreat cap is only a safety net.
- Combat cap: after 12 rounds the monster retreats for half score (bounded fights per the "short 3-6 round" spec).
- HP 0 = dazed (sits out), never dead; a full wipe ends the expedition (clean, avoids deadlock with all-dazed retreats).
- Challenge/trap rooms: one specific player rolls, rotating fairly (challengeIndex), using the same Language Check setting as any action.
- NPC companion auto-joins for 1-2 players (or when toggled): Cleric, or Warrior if a Cleric exists; acts automatically (helps solo/tiny classes; teacher can turn it off).
- Expeditions = 9 rooms from one themed deck (Forest/Crypt/Ruins): combat x3, challenge, trap, treasure, rest, event + final boss (themed coherence, boss finale, within 8-10 rooms).
- Undo via a cap-60 snapshot history in the state layer; reroll re-resolves the last action with a fresh die keeping language/assist bonuses (teacher tools for free).
- Old v1 saves are ignored (schema bump to 2) (avoid crashing on stale shapes).
- All UI features are verified by headless-Edge tests that drive real clicks/keypresses and assert visible DOM text (user cannot test code; "green" engine tests alone are insufficient).
- Global window.onerror + unhandledrejection banner with a Copy button on every page (a silent blank page must never happen again).
- B0 UI (gm.js/stage.js) is plain-functionality styling using the AGENTS.md section 5 palette; art work (sprites, d20, typewriter, pixel font) is deferred to B1.
- B1 stage.js is the final JRPG battle layout (enemies right, party left, bordered bottom menu window, damage numbers, d20 face with roll breakdown, typewriter narration) + title screen with code-drawn pixel logo and animated backdrop. Reset for reduced motion.
- Sprite manifest (assets/sprites/manifest.json) maps every character/monster/portrait to a PNG path, frame size (party 32x48, enemies 64x64, bosses 128x128, portraits 64x64), and frame list; missing PNG -> code-drawn placeholder. Documented in SPRITE_GUIDE.md.
- Sprites: all current art is code-drawn placeholders in src/engine/sprites.js (FF4-style simple/classic): hero palettes per class, slime/bat/golem/bird shapes per monster. No external images yet (art pending).
- Audio: Web Audio chiptune SFX (click/hit/crit/fumble/dice/heal/victory/levelup) + looping arpeggio music, no files; initAudio resumes on user gesture; mute hook (setMuted) ready for a B2 UI toggle.
- Fonts: self-hosted OFL pixel font Press Start 2P for headings/logo + VT323 for long text in /assets/fonts (OFL, logged for CREDITS later).
- Typewriter text (click/Enter skips) via src/ui/typewriter.js; respects prefers-reduced-motion (instant print).
- Global error handler's file:// guard waited for body before appending (runs in <head>); fixed so the message actually shows when opening index.html directly.
- B1.5 (audit-driven): stage.html + gm.html are the PRIMARY mode; index.html is secondary. Stage is a fixed 16:9 virtual canvas, scaled to fit with letterboxing (width min(100%, 100vh*16/9), aspect-ratio 16/9, --ss scale var), so drawer/canvas/sprites stop breaking resolution (layout.mjs verifies geometry at 5 viewports).
- B1.5: sprites use INTEGER scales only (intSpriteScale = round(base * stageScaleFactor)), image-rendering pixelated everywhere, so pixel art stays crisp at any projector size.
- B1.5: Stage zones = top-right minimap (expedition room nodes from existing data, placeholder only), center battlefield, bottom menu; text is >=28px at 1080p via --ss scaling; pixel font is for logo/titles ONLY (title-logo/app-title/big-title), all panels and headings use VT323.
- B1.5: in index.html the GM drawer DOCKS beside the Stage (stage rescales into the remaining 16:9 area) instead of overlaying it; GM button hides while drawer is open (display:none via sibling selector). gm.html is a normal responsive page, no floating button.
- B1.5: typo "The The Whispering Forest" fixed at source in content/prompts.json expeditionStart template ("The {deck}" -> "{deck}") because deckName already contains "The".
- B1.5: ResizeObserver re-measures --ss and re-renders stage on any resize (so drawer open/close rescales the Stage correctly).
- Step C (story plumbing, in progress): content/episodes.json holds scripted episodes; episode = ordered scenes (story = d20 + language-check roll that decides progress via onGood/onBad, combat = monster fight reusing the expedition combat engine).
- Step C: startEpisode() builds the episode into the same expedition-shaped state (buildEpisodeExpedition in src/engine/episode.js), so story scenes reuse the existing challenge/roll/language machinery; scene-specific prompts (text/target/example) replace random vocab prompts when present.
- Step C: per-scene outcomes (onGood/onBad) are logged as narration; success sets flags into expedition.flags (the "flags/memory" of what the party did), accessible for conditional scenes later.
- Step C: episodes.json is validated (duplicate ids, stat/difficulty/monsterId/prompt checks) + cross-referenced (combat scene monsterId must exist) in content.js; the GM lobby shows a "Story episodes" section with a Play button per episode.
- Step C: the shipped episode is "The Bell of Bellingham" (6 linear scenes: 5 story + 1 combat) where English output (judged Weak/Good/Great) decides whether the good or bad outcome is narrated.
